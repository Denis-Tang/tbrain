# Tbrain 桌面长任务评测

本页整理北京时间 2026-11-04 至 2026-11-05 运行的隔离评测，供 README 方法与数字复核。控制记录中的时间使用 UTC，转换后六条正式链的首个工程发令最早为 11 月 4 日 14:13，最后探针发令最晚为 11 月 5 日 01:26。Tbrain 在本次任务中减少了新会话接续答题的输入用量，但质量、时间和记忆维护各有得失。每个宿主/条件只有一条独立开发链。

## 被测条件

| 项目 | 版本或方式 |
|---|---|
| DSH Desktop | ASAR 版本 `0.2.1-rc.5`，Windows 文件版本 `0.2.1.0` |
| Pi Desktop | `0.8.2` |
| Tbrain | `0.7.0-beta.1+lab.1`，修复快照重复保存的实验兼容版 |
| Basic Memory | `1.0.0`，本地模式，各组专用项目 `bench` 与独立笔记库，通过 stdio MCP 接入 |
| 模型与路由 | `deepseek-v4.1-flash`，两款宿主经同一本机 `lite-relay` 路由 |
| 推理配置 | DSH `reasoningEffort=medium`，Pi `defaultThinkingLevel=medium` |
| 客户端窗口声明 | 两款 `contextWindow=1000000`，Pi 另配置 `maxTokens=16384`，未独立验证上游实际有效窗口 |
| 平台与隔离 | Windows，Sandboxie-Plus `1.18.8`，六个正式条件各用独立应用箱 |

原 Beta `0.7.0-beta.1` 在 Sandboxie 内重复创建已有快照硬链接时失败，因此正式成绩属于兼容版。0.7.0 纳入该兼容修复，另做本地回归和分发包验证；本页数字不是对 0.7.0 重新运行的六组横评。

DSH 使用桌面运行时的 sessionController，Pi 使用桌面自身的 Agent API 调度。工程执行、模型调用和会话持久化由实际桌面运行时完成。另对两款桌面窗口各做一次键盘输入与发送补测，GUI 结果单列。

### 插件、扩展与权限配置

| 条件 | 共同运行组件之外的记忆接入 | 实际调用路径 |
|---|---|---|
| DSH 原生 | 宿主历史、本组工程笔记 | 原生历史与文件读取 |
| DSH Tbrain | Tbrain 通用 MCP 四工具 | DSH MCP 客户端调用 Tbrain，模型填写宿主 ID |
| DSH Basic Memory | Basic Memory MCP | `@deepseek-ai/dsh-mcp-client` 启动本地 `basic-memory mcp --project bench` |
| Pi 原生 | 宿主历史、本组工程笔记 | 原生历史与文件读取 |
| Pi Tbrain | 被测包提供的 `tbrain.ts` 扩展 | 扩展绑定真实宿主 ID，再调用 Tbrain CLI 四工具 |
| Pi Basic Memory | 桌面 MCP 配置，`exposure=direct` | 本地 `basic-memory mcp --project bench`，工具直接暴露给 Agent |

DSH 三种条件统一加载一次性插件 `tbrain-bench-desktop-driver`，通过 `sessionController` 发令并记录 `session/event`，选择同一模型和 medium 推理档位，设置 `danger-full-access` 权限。DSH 内部重复 ACL 限制关闭，Electron 启动参数包含 `--disable-features=PrintCompositorLPAC --disable-gpu --no-sandbox` 及每组独立 `--user-data-dir`。这些调整用于处理实验环境中的 Shell 与渲染故障，外层 Sandboxie 保留。插件调度、权限与启动条件对 DSH 三组相同。

Pi 三种条件通过桌面自身 Agent API 调度，使用应用原生 PowerShell 工具。核对保留的用户扩展目录，Tbrain 条件有 `tbrain.ts`，原生与 Basic Memory 条件未在该目录发现扩展。该目录核对只覆盖用户扩展文件，宿主随包内置的组件仍由桌面版本决定。

六组都提供相同项目背景、源码 `AGENTS.md`、项目内 `source/.agents/skills/docetl` 技能，首阶段指令要求先阅读该技能。工程笔记、原生历史和网络调研均可使用，原生组也可使用自己的持久笔记。额外记忆接入和相应的条件提示是组间差异，没有逐次统计每项技能的实际调用。

## 任务与计分

任务为酒店知识库转换程序的审计与改进。五个阶段依次是代码审计、最小修复、离线导出简化、真实模型转换对照、冻结后独立材料验证与打包。

每链从相同材料及空任务记忆开始，计划使用首个工程会话和五个新会话，共六个宿主会话、五次切换。控制器按阶段主动新建会话，每次先只读检查记忆，再在同一会话推进下一工程阶段，最后一次只读检查最终状态。中断后恢复原会话单列。原生组允许读取自己的历史和手写工程笔记，所有组都能进行工程工作及网络调研。

- **核心检查：** 每链 59 次已知事实恢复、10 次无答案识别，共 69 次；包含同一事实在多个会话的重复保持。
- **严格工程接续：** 四个可执行切换点，必须正确恢复真实工程状态并完成后续动作。
- **最终状态：** 最后一次探针只读核对源码、交付物、验证与剩余问题。
- **答题成本：** 新会话发令到首份完整答卷的输入、输出、工具数和墙钟时间；失败检查点保留。

所有子条件满足才计通过；与材料矛盾的附加断言也会失分。Codex 对照原始消息、源码、工具记录和产物评分，未经外部人工盲标。维度参考 LongMemEval，但没有运行其标准数据集。

59 次已知事实恢复的组成是第一次探针 7 项、后四次各 13 项，无答案识别每次 2 项。工程状态问题 Q9 独立核对实际产物与后续动作，计入四个工程接续点及最终状态列。Q12 的新契约学习与来源纠错补测单列，均未加入 69 次核心检查。控制器的主动会话切换也未提供可比较的原生上下文压缩成功率。

## 失分与工程边界

- **DSH Tbrain：** 对开发材料来源的同一误判在两个探针中重复，失两分。一处工程接续错误恢复了材料使用状态，因此严格接续为 3/4；技术动作完成不能替代材料约束验收。
- **DSH Basic Memory：** 一次误称已删除的依赖联接仍存在，另一次误记材料验证历史。
- **Pi 原生：** 正确说没有设定 SLA，却附加了与已有试测记录矛盾的断言，失一分。
- **Pi Basic Memory：** 同一撤销日期误记重复三次，不能解释成三个独立日期错误。

DSH Tbrain 冻结后的来源更正补测为 4/4 原子项通过，但控制器提供了文件线索，不是自主发现错误；旧错误 K 的退役也未由这次补测验证。补测不回改正式成绩，不混入五次探针成本。

## 接入与记忆维护限制

**DSH 会话 ID 与原话链路没有通过完整验收。** 正式链手动 MCP 调用中，bootstrap 3/8 次传入真实宿主 ID；save 12/24 次匹配真实 ID，15/24 次整次无拒绝，8/24 次同时满足两项。错误关联仍在本组知识库内，未观察到跨组记忆写入。

**Pi 的 ID 由扩展绑定。** bootstrap 3/3、save 28/28 的返回 ID 匹配真实宿主；save 整次无拒绝为 13/28。有拒绝的调用可能已部分写入或随后补交，不能据此推算同等比例的最终记忆丢失。

| 原话全文匹配 | 桌面 API 发令 | 真实 GUI 补测 |
|---|---:|---:|
| DSH Tbrain | 0/10 | 0/1 |
| Pi Tbrain | 10/10 | 1/1 |

原话按真实宿主 ID 对应的实际 U 条目匹配，只规范换行和首尾空白。`saved_users` 是整理水位，不是采集条数。GUI 每宿主仅一条，不能推广为长期采集成功率。

**旧决定退役仍有缺口。** Pi 的两个新值能正确恢复，但原记录未正式失效，阶段二及阶段五的旧值退役检查均为 0/2。DSH 的旧交付值有失效标记，但阶段授权改变后，旧禁令到下一阶段才从项目规则清除。答对新值不等于及时维护了所有旧记录。

## 适用范围

六链首个工程发令至最终探针发令的墙钟跨度为 2.275–4.865 小时，包含调度和等待，不能当作持续活跃工作时长。DSH 顺序为原生、Tbrain、Basic Memory；Pi 顺序为 Basic Memory、原生、Tbrain，未完整随机化。

同一事实的多次检查不能替代独立重复。各组代码方案、工具选择、输出长度、网络等待和控制器干预均有差异；上游前缀缓存未重置，机器非独占运行，归一价格也无法消除这些影响。观察不能单独归因于记忆算法。

本次测量同一宿主的新会话接续，没有测量 DSH 与 Pi 共用知识库的跨宿主接力，也没有形成可比较的原生压缩成功率。隔离探针覆盖了明确路径与操作，不是全系统隔离认证。

公开材料保留汇总口径、六组数据、失分和限制；原始工程材料、宿主记录和私有配置不随仓库发布。后续需要多条独立开发链和新的任务主题，再判断能否提出更强的质量或效率结论。
